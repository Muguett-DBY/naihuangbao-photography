## 3. 已确认并修复的软件缺陷（6 项）

### 3.1 「下一课」按钮在书尾被错误吞掉（HIGH）
- **位置**：`src/pages/LawLessonPage.tsx`
- **根因**：用 `lessonRef.order < book.lessonCount` 判断"还有没有下一课"。`order` 按全书课时数（**含**空壳/附录课）累加，`lessonCount` **不含**它们——两边口径不一致。书尾凡是"序号 ≥ lessonCount"的真课时，「下一课」被替换成"全部学完了！返回目录"。
- **影响面**（修复前实测计数）：民法 62 课 + 法制史 1 课 = **63 个课时提前断流**（其后明明还有学习流课时）。
- **修复**：改为直接查询"下一个学习流课时是否存在"（新纯函数 `nextFlowLesson`），删除序号比较。
- **回归**：`src/lib/law-nav.test.ts`（"never dead-ends before the last flow lesson"）。

### 3.2 「下一课」直接落进无正文的死页（HIGH）
- **位置**：同上（旧 `nextLessonOf` 不做任何过滤）。
- **影响面**：民法 76 处 + 法制史 1 处"下一课"落进**空壳索引课**（整课只有 1 个标题词，如 `minfa-q032` 全课内容就是「主体」两个字）；法制史的还会落进 92 课时的附录索引章。用户点「下一课」看到的是没有可学内容的死页。
- **修复**：`nextFlowLesson` 跳过空壳课与附录章课时。
- **回归**：`law-nav.test.ts`（"never navigates into a shell or appendix lesson"）+ E2E「下一课跳过索引空壳课」（minfa-q031 → 必须直达 minfa-q033，跳过 q032）。

### 3.3 附录索引章混进目录/搜索（HIGH）
- **位置**：`src/types/law.ts`（缺字段）、`LawSubjectPage`、`LawSearch`。
- **根因**：构建端已给《法制史》断代考点索引章打 `chapter.appendix = true` 并从 `lessonCount` 剔除（98 课时），但运行时类型与 UI 完全不认识该标记——92 个索引课时照样出现在章节目录与全文搜索里，且学科页头部的"知识点总数"与目录实际条目数对不上。
- **修复**：`LawChapter` 增加 `appendix?`；目录与搜索过滤附录章；附录内容以折叠区（「📎 附录 · 考点速查索引（不进学习流）」）完整保留、可查阅不丢失。
- **回归**：`law-content.test.ts` 新增附录章断言 + E2E「附录章不进章节目录」。

### 3.4 CompareStep 同帧双击可致步骤永久卡死（MID，交互死角）
- **位置**：`src/components/law/player/steps/CompareStep.tsx`
- **根因**：完成判定写在 `setState` **外面**，读的是渲染闭包里的旧 `revealed`。两次点击落在同一渲染帧（移动端双指同点两行）时，两次都按旧值计数 → "全部翻开"漏判 → `onDone` 永不触发 → 「下一步」永久禁用，而界面却显示"对比看完了 ✓"。其余步骤（List/Condition/Mnemonic/Flow/Timeline）都在 updater 内判定，唯独 Compare 不在。
- **修复**：判定移入 updater，与其他步骤同构（`doneRef` 防重入）。
- **回归**：组件级交互用例由 `law:flow` + E2E 完整学习流覆盖（无 React 单测环境，未新增组件单测）。

### 3.5 定义步骤展示"句子里不存在"的关键词（MID，53% 步骤受影响）
- **位置**：`src/components/law/player/steps/DefinitionStep.tsx`
- **根因**：`terms` 在构建期按**整块文本**提取，而长块会被按句切成多个步骤（携带同一份 terms）。播放器取 `terms[0]`，与当前句无关——实测 **2412 个带 terms 的步骤中 1272 个（53%）** `terms[0]` 不在本句文本里，关键词胶囊展示的是别句的词。
- **修复**：取**第一个确实出现在本句**的术语（`step.terms.find(t => text.includes(t.term))`），取不到再退回 `tellTerm` 现场提取。
- **说明**：PlainStep / SentenceLines 本来就按"在文本中"过滤，不受影响；此修复使 Definition 步骤对齐同一标准。

### 3.6 OCR 糊句被当成"原句判断题"出题（HIGH，题目不可作答）
- **位置**：`src/lib/law-quiz.ts` `isCleanVerbatimSentence`
- **实例**：minfa-q482 判断题「合同目的是为了满足社会公众的生活需要，故供应人有强制缔约目的义务**算二〇典合国**。」答案"是"——题面尾部是 OCR 糊块，用户根本无法判定。
- **修复**：判断题取材新增两道滤网：含 `○□◊` 占位符的句子直接排除；`〇` 仅当年份写法（后接 `〇/数字/年`，如"二〇二五"）才放行，"〇后接普通汉字"（糊块特征）排除。两种判断题（改年份答"否"/原句答"是"）共用该滤网。
- **回归**：`law-quiz.test.ts` 新增「rejects OCR-garbled sentences as verbatim judge questions」（糊句禁用 + 年份句不误伤）。

## 4. 内容/数据发现（只报告；修复需原书或属构建管线）

### 4.1 构建回归：minfa-c22 语义名缺失（当前唯一红测）
- `minfa/minfa-c22`（第五编·第三章，8 课时：无因管理 + 不当得利）`semanticTitle` 为空，`law-content.test.ts` 的"多课章节必须有语义名"断言失败。
- **根因**（已定位，构建管线）：`pickSemanticTitle` 的课时标题回退链不剥数字题号前缀。"5-161．简述无因管理的构成要件" 清洗后长度 12 > 10 上限被拒，全部候选落空。
- **建议一行修复**（构建管线维护方）：回退清洗链加 `.replace(/^\d{1,3}-\d{1,3}[.．、]/, "")`，即可得「无因管理」。运行时兜底会显示面包屑名"无因管理"，不致乱码，但目录可读性受损。

### 4.2 疑似真截断（65 步，需要原书誊录补全）
句末悬停在 的/并/而/与/或/其 等虚词或介词上、无法自足成句（已剔除"目的/义务/行为/事由"等合法名词收尾的 100 例）。分布：刑法 34、民法 13、法理 7、宪法 8、法制史 3。样例：

| 课时 | 尾部 |
| --- | --- |
| xianfa-q014-s0 | …79 年的《人身保护法》；**1689 年的** |
| zhishixiang-q084-s1 | …河南的"写户"，**浙江的** |
| minfa-q078-s0 | …依法指定监护人**作为** |
| falixue-q176-s6 | …应听取当事人的意见。其理论根据主要**是** |

**处理原则**：不猜测、不杜撰原文。建议按 §4.1 同款"人工修表"（`scripts/law-manual-fixes.json` 机制）对照原书逐条誊录。

### 4.3 OCR 残渣（12 步 + 63 原文行）
- 正文含占位/糊字 6 步（如 xingfa-q320「第十一分**〇**贪亏须客体…」= 运行页眉焊进正文；falixue-q068「［种类拆解］」边栏标签残留）。
- 拉丁残块 6 步（`Who/How/Feel/shr/gou` 页眉遗迹）。
- 原文对照层（`raw`，仅"原文对照"面板可见）残留页眉/页脚变体 63 行——`raw` 本就是未清洗保底层，风险低，但搜索摘录会切到它们（见 §6）。

### 4.4 页眉焊接（剩 1 处；今晨已由管线方修复 8 处）
正文句中焊入糊版页眉「法律硕士考试背诵一本通·X学」类残迹。审计开始时发现 9 处（民法 3、宪法 2、法制史 2、刑法 1、法理 1），构建管线当日上午的修表已清除 8 处，现存唯一一处：
- `falixue-q054-s0`：「…合目的性原则先应当坚持的原则**法律旗土考试臂街一未殖·法单**划分法律部门时应注意…」——删除该糊块后语句连通，边界清晰，可直接进修表。

### 4.5 标点与括号（250+ 步，低危）
- 括号不配对 212 步（多为 OCR 丢半个书名号/注记括号，如「」差 -1）。
- 异常标点序列 34 步（`，；` `。，` 残留拼接）、句首标点 6 步（分步切分把断句切开）。
- 全部属展示瑕疵，不阻塞交互；无自动修复的可靠判据（可能是列表/表格结构本身）。

### 4.6 重复内容（6 处，低危）
- 完全重复的两个导览课：`zhishixiang-q164-tour ≡ q034-tour`、`zhishixiang-q186-tour ≡ q113-tour`（思维导图页被 OCR 双读或原书重复页；删除需确认原书页码）。
- parts 内非相邻重复条目 2 步（minfa-q256「拾得人」×2、minfa-q514）、空字符串 part 3 步（列表渲染一张空卡）、连续叠字残迹 2 步（falixue-q187「全面依法治国的政治方向×2」、zhishixiang-q083「个个个个个个」）。

### 4.7 步骤类型与数据不匹配（8 步，低危）
- 3 个 exception 步正文无 但/除外/例外（如 xingfa-q056）→ 组件回退把整段文本当"但书"展示，语义误导但不卡流程。
- 5 个 flow 步无可拆节点（单节点流程）→ 显示"流程 · 1 步"，可完成，体验平淡。
- 165 个"句末无终止标点"步骤中 100 个是合法名词收尾（行为/事由/目的…），构建端 `restoreTerminal` 有意保守不补句号——维持现状正确。

### 4.8 题目质量全量核验（2558 题，线上同款生成参数）
**零命中**（即以下问题一个都不存在）：选项重复、选项互为子串、答案不在选项内、答案泄漏在题面、干扰项出现在题面（歧义）、答案不出自本课、判断题原句不在课文、排序项重复/不在课文、解析为空、题目 id 重复。存在但属设计内：
- 8 题 MCQ 只有 2 个选项（同章干扰词不足时的保底出题）；
- 3 题判断题题面 ~100 字（题面=引号整句，长但可读）；
- 166 个课时无自动题（长文讲述型）→ 总结页走"标记掌握"路径，有明确 UI 提示，不算缺陷。

### 4.9 结构一致性（通过）
- `lessonCount` = 学习流课时数，逐科与 stats.json 一致（法理 187 / 宪法 103 / 法制史 196 / 民法 647 / 刑法 387）。
- 83 个空壳课全部为"纯标题"形态且不计入总数；非空壳课 100% 有 `raw` 原文（保底承诺成立）。
- 13 张图解全部锚定到真实非空壳课时。
- 多课章节语义名：除 §4.1 的 minfa-c22 外全部合格，无纯序号名。

### 4.10 SRS（间隔复习）状态机审查
- 主链路正确：答错 → stage 0 + 1 天后到期 → 连过 1/2/4/7/15 天梯度 → 五连过毕业移出错题本；`getWrongLessons`/`getDueReviewLessons` 过滤与排序逻辑与设计一致（单元测试 9 例覆盖）。
- **两条设计观察**（非缺陷，提请确认）：
  1. 总结页「跳过自测，直接标记掌握」调用 `recordQuiz(1,1,…)`，会**推进错题的复习阶段**——跳过测试算复习通过，可能过宽；
  2. 复习期内再答错重置回 stage 0（+1 天），符合预期。

### 4.11 长文移动端溢出风险（低）
- 数据极值：课题最长 40 字、步骤最长 674 字（43 步 >300 字，超长步骤按句分页渲染）、选项 ≤12 字、排序卡 ≤40 字。
- CSS 审查：正文/选项/原文面板全部 `pre-wrap` 或纵向 flex，CJK 自然换行；排序卡容器 `flex-wrap`。**无横向溢出路径**。两个体验项：时间线 >5 节点时窄屏年代标签拥挤；932 个 parts 条目 >64 字在列表卡内换行显示（可读，无截断）。

### 4.12 搜索摘录（可用，有已知噪音）
摘录机制（定位关键词 → 前后 18/64 字切片 + 省略号）无截断 bug；但摘录直接切自 `raw` OCR 层，§4.3 的 63 行页眉残渣与 OCR 噪音可能出现在摘要里。建议（非必须）：摘录源改用 `steps` 文本（已清洗层）。
